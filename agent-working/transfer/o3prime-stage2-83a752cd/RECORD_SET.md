## What runs and how
Each process: `systemd-run --user --scope -q -p MemoryMax=3G -p MemorySwapMax=0 taskset -c 4-5 setsid -w <python> subject_trace_run.py one ...` (in the launcher, each kit python call with cd $KIT and PYTHONPATH), TMPDIR on /data (`<OUT>/cells/tmp`), PYTHONHASHSEED=0, SIM_OBS_MODE=OFF, RPG_OBS_MODE=OFF (recording OFF), **PYTHONDONTWRITEBYTECODE=1 exported for every process and python -B for anything ad hoc**; a watcher per process (summed RSS above 2.85 GiB kills it); before each process the heavy-job check, MemAvailable >= 3 GiB and the disk floor (>= 2 GiB free on OUT and /); freeze checked after every process. **OUT = `/data/vboxuser/o3-trace-runs/83a752cdebb64a20224b764727b41a76f08adaa5/stage2/cells` (does not exist; the launcher creates it, writes the per-cell files, `cell_validity.json`, `runner.json`, and seals LAST; nothing is deleted).**
The spy (`subject_trace_spy`) per tick in each subject's windows, BEFORE and AFTER the apply: movement mode; task action, reason and payload; goal tile and path length; navigation failure_reason; readiness; hp; state ALIVE/DEAD/ABSENT (a dead or removed subject is still recorded); position; distances to every counterpart and to the goal tile; the strategic objective; and the motive reads (relation both ways in each arm's own form, attacked_me_recently both ways, objective, reason) per counterpart on the prior state. The legality wrapper is pass-through (the original result or exception goes through unchanged) and records only subject-as-attacker calls in the window, with tick = context.tick if present else world_time + offset, tick_source, raw world_time; `offset_drift` voids the cell. Evidence only: stage 2 gives no verdict.
