### Governing-file edit attempts (report-only)

_Rows are written by the guard at PreToolUse, so each is an ATTEMPT. `edit` rows (basis `path`, an edit tool) are exact; `mention` rows (basis `mention`, a Bash command naming the path) may not be edits and over-count. Edit-tool rows for files outside the repo are not written. Merged commits are counted by path and period from `origin/main`, with the same path list the PR body uses; an attempt cannot be tied to one PR body._

Edit attempts with no merged commit on that path in the period: none.
Governing paths with merged commits and no edit attempt row in the period: none.
_Unmatched means one of: the edit was reverted, the call was denied or failed, the work has not merged yet (an attempt in one week can merge the next), or a real edit never went through review. A merged path with no attempt row can mean the edit was made where no row is written (see the limits below), or its rows sit on an unmerged branch or the other host. Rows reach main only when a branch carries them, so a missing row can also mean its branch is unmerged. A prompt to look, not a violation count._
_Limits: a Bash edit that does not name the path from the repo root (e.g. `cd tools/sessions && sed -i ... guard.py`) or that sits inside an interpreter payload writes no row, so an empty count does not mean no edits. A mention can also name a same-suffix file outside the repo (e.g. a user-level settings file)._
