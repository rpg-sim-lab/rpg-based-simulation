## 1. Content schema
- `species.yaml`: optional `reproduction_profile: <id>` (same shape as `need_profile`). No profile = no births (content, not a code default).
- New `data/content/living/reproduction_profiles.yaml`, fields all required: `birth_chance_per_check` (0-1), `min_birth_interval_ticks`, `litter_size` (int >= 1, fixed in M1; the system reads it and M1 data sets 1), `mate_radius_tiles`, `fed_line`, `birth_hunger_cost`.
- Loader (`src/content/`: schema.py, repository.py, validator.py): typed refusal `ReproductionProfileOnNonEatingKindError` when a species with a profile has a need profile whose `hunger` is `"none"`; also a typed refusal for an unknown profile id and for out-of-range fields. Undead, spirit, slime and dragonkin declare no profile (owner B2).
- Units: hunger is 0-100, higher is hungrier. `fed_line` is the highest hunger that still counts as fed. Time: 2400 ticks a day (calendar.py), a 30-tick check = 80 checks a day. Hunger per day = 2400 x 0.1 x level scale: low (people, orc, elf, dwarf, troll, lizardfolk) 120/day, very_low (wolf, spider) 72/day, medium (goblin, small_plant_eater) 240/day. Existing lines: hungry above 70, weakened 85, starving 95; an inn meal is 40, a meat unit 20.
- Values, fixed here before any data, never tuned on own-job data. **[D1] rpg-designer-ubuntu signs off this table before the pin commit.**

| profile (kinds) | birth_chance_per_check | min_birth_interval_ticks | litter | mate_radius_tiles | fed_line | birth_hunger_cost |
|---|---|---|---|---|---|---|
| humanoid_births (human, orc, elf, dwarf, troll, lizardfolk) | 0.005 | 12000 (5 days) | 1 | 10 | 30 | 25 |
| carnivore_births (wolf, spider) | 0.004 | 12000 | 1 | 10 | 30 | 25 |
| goblin_births (goblin) | 0.008 | 7200 (3 days) | 1 | 10 | 30 | 25 |
| plant_eater_births (small_plant_eater) | 0.008 | 7200 | 1 | 10 | 30 | 25 |

Sources: chance 0.005 per check = a mean wait of 200 checks, about 2.5 days, for an eligible mother (roughly 0.4 births per eligible mother per 5000-tick run); the fast breeders (goblin, plant-eater) get 1.6x, the carnivores 0.8x. Interval: a birth is a multi-day event at decision 33's time, so a pair does not breed twice inside one run. `fed_line` 30: hunger 30 is 6 hours after a full meal for a person (30/120 a day), 10 hours for a wolf, 3 hours for a goblin; "well-fed" means a recent meal, well under the hungry line of 70. `birth_hunger_cost` 25: a little under one inn meal (40), so a mother just under the fed line is pushed to 55 and has to eat again before the next. `mate_radius_tiles` 10: carried from the old `HUMANOID_PAIRING_RADIUS`, now Chebyshev.

## 2. One births system (authoritative path)
- New `src/world/births.py` (`BirthService.process_births(state, generator) -> StateUpdate`, read-only on state, returns a typed update; ApplyPath is the only writer). Cadence: one `SystemCadence.births = 30` field, replacing `reproduction_humanoid` (200). Hook: world_dynamics.py section 3.10, unflagged, `should_run(tick, None, cadence.births)`.
- Per check: candidates = alive, active, ADULT bodies whose species declares a profile, sorted by id. Mothers visited in id order. A body already used as mother or mate in this check is skipped (each entity is a parent in at most one birth per check, W1).
- Mother eligible: ADULT, alive, active; `hunger <= fed_line` (her own hunger only, nothing regional); cooldown-eligible. Mate: the lowest-id other body with the same `species_of()`, alive, active, ADULT, within `mate_radius_tiles` Chebyshev, cooldown-eligible, not used this check. No sex, no pair bond.
- Draw: `generator.rng.get_float(Domain.SPAWN, tick, mother_id, sub_id=<fixed births id>)` compared with `birth_chance_per_check`: stateless and keyed (world seed, tick, mother id). The draw happens only after the mother and a mate are known to be eligible, so the cooldown and mate checks never consume order-dependent randomness (it is stateless anyway).
- Spatial scan: `SpatialQueryService.nearby_entities` returns a set; filter to the Chebyshev radius ourselves. Verify its radius metric when coding; query radius = ceil(mate_radius_tiles x sqrt 2), then filter.
- Output of a birth (one StateUpdate per pair, merged in mother-id order): `entities_add=[newborn]`, `entity_spawn_sources={id: SpawnSource(BIRTH, parent_ids=(mother, mate))}`, mother `BiologicalUpdate(hunger_delta=+min(cost, 100 - hunger))` (W4 wording in v2), both parents' `reproduction_cooldowns_add={partner: tick + min_birth_interval_ticks}`, and `WorldUpdate(population_young_births_delta=1)` for the mother's region (merged additively), plus the existing `build_parent_bond_updates_for_birth`.
- Region scarcity suppression: the old humanoid and camp paths skipped a birth when `compute_regional_scarcity` exceeded the young cohort threshold. Q2 says the check reads nothing regional. **[D2] The plan drops the scarcity suppression and retires the tests that pin it (listed in section 5). rpg-designer confirms.**

## 4. The newborn
- Kind = `species_of(mother)` (= the mate's by construction); occupation None; `parent_a_entity_id` = mother, `parent_b_entity_id` = mate, `birth_tick` = tick, set through `birth_record` (genetics and reputation combine as the old humanoid path did). Role: MONSTER if the mother's role is MONSTER, else CITIZEN. Faction: the mother's. age_ticks 0, gold 0, `LifeStage.CHILD`. Hunger = the kind's t0 starting value (the builder default, 0.0, checked when coding); the mother's cost is the only hunger event at birth.
- Body (Q11, ruled): built through the SAME species/archetype path as a t0 body, any seeded draw keyed by the newborn id, t0 stats at full HP, no CHILD scaling. A new `ArchetypeEntityFactory.build_newborn(...)` takes the resolved contract and overrides role, faction, occupation (None), gold (0), age (0), life stage (CHILD) and the birth record, so the factory remains the one writer of body stats and personality.
- **[D3] Which archetype?** A species has several archetypes (wolf: hungry_wolf, alpha_wolf), and the classic compile path (`worldbuilding/compiler.py` around line 700) builds t0 bodies from a population profile and writes no `archetype_id` property. Plan: the newborn takes the mother's `properties["archetype_id"]` when present; otherwise the species' first declared non-leader archetype by id order (a content lookup, never a default species). The first coding step checks which of these the three gate worlds' bodies carry. If bodies carry no archetype id, I STOP and ask rather than inventing one. Recommendation to rpg-designer: the mother's archetype with a "no alpha newborns" rule needs its own ruling; I propose the species' base archetype instead.
- **[D4] A CHILD never grows up inside any run.** `LifeStageService.get_stage_for_age` ends CHILD at 3,456,000 ticks (12 fantasy years). With age_ticks 0 (Q11) a newborn is a CHILD for the whole run and never becomes a mother or mate (births need ADULT). The old natural-creature path started near the boundary on purpose (`short_clock_age`). This is consistent with the ruling, but it means a second generation never exists in a measurement and "camps refill by births" is a one-generation refill. I disclose it in the step report; no path treats CHILD as ADULT. Raised to the planner in case the owner wants a maturation ruling later.
- LifeStage gates found at 3aafdb383 (`grep -rn "life_stage\|LifeStage" src`): ai/life_stage.py (CHILD goal multipliers: combat 0.2, harvesting 0.5, applied in ai/score_modifiers.py:26), systems/lifecycle_systems/lifecycle.py:187-214 (age-based forward transition; the Coming-of-Age archetype roll requires role CITIZEN and a birth record, so a CITIZEN newborn takes it at adulthood, a MONSTER newborn does not), ai/coming_of_age.py (birth_tick and birth-record exclusion), domains/demographics/cohort.py (age brackets), engine/patches.py:210-248 and core/updates.py (life_stage_set). Births gate on ADULT. Every one keeps gating the newborn as CHILD; I add no change to them, and a test pins that a newborn gets the CHILD goal multipliers.
